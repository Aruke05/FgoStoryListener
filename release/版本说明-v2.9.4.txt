FGO 剧情文本监听器 v2.9.4

定位结果
- 卡顿不只来自模型：游戏 LOG 每追加一句时，旧版会同步删除并重建主窗口中的全部历史行；长 LOG 还会反复建立 O(n*m) 对齐矩阵。Tk 事件回调结束前不会重绘，因此缓存命中也会表现为晚几秒。
- 当前数据库中普通预载命中可本地立即显示；最近未缓存的选项/分支实际远端耗时约 11、11、14 秒。

本版改动（以 v2.9.3 功能为基线）
1. LOG 与剧情预载改为增量更新，不在实时事件中全表重建。
2. 通常追加式 LOG 使用经过完整序列校验的 O(n) 对齐；乱序/冲突才回退到原 LCS。
3. AddText 原文当帧显示非持久预览；220ms 仍只用于保证最终记录不缺字、不碎片化。
4. 当前句使用 latest-wins：新句会中断仍占用实时通道的旧句，旧句随后自动补译。
5. 中文按 Codex 输出流式显示；完整剧情仍是一批最多 100 条、一次 Codex 请求，但每完成一个对象即写入数据库，不再等整批结束。
6. 恢复并验证 v2.9.3 的精确片段组合、剧情选项翻译复用；“已选择”不重复消耗 Token。
7. 实时与预翻译各有独立 app-server，Sol/high 后台批次不阻塞当前句。

验证
- 68 项单元/回归测试全部通过。
- hook.js 通过 node --check；Python 源码通过 py_compile。
- 真实 codex app-server 翻译烟测通过：收到 token 预览、两个逐对象回调和最终结构化结果。
- 1000 条 LOG 基准：首次导入约 0.086 秒；追加到 1001 条约 0.036 秒。
- 安装包 hook、Schema、知识库和 README 的 SHA-256 均与源码目录一致。

已知边界
- 缓存未命中的临时剧情选项仍取决于远端 Codex 首 token；本次真实烟测首 token 约 19.2 秒，说明服务端偶发等待无法由 Windows 客户端完全消除。
- 本版会立即显示原文并流式显示已返回的中文，但不会用低质量猜译冒充最终译文。
- 原版 v2.9.3 仍保留在 dist-v2.9.3，可随时回退。
